# ADR 0002: 4계층 폴더별 컨텍스트 문서와 컴포넌트 카탈로그

- 상태: 채택
- 날짜: 2026-10-15
- 관련: [ADR 0001](0001-agents-md-as-ssot.md)

## 배경
- **성격 변화:** 이 프로젝트는 CIRA 전용 앱이 아니라 UI 학습과 웹 기능 실험장입니다. 처음 정리한 문서는 CIRA 이외의 코드를 "레거시"로 분류하고 있었습니다.
- **개발 방식:** 미리 만든 컴포넌트를 화면에서 조립하는 방식으로 개발합니다. AI 도구가 "재사용할 수 있는 컴포넌트"를 바로 찾지 못하면, 비슷한 모달이나 버튼을 매번 새로 만들게 됩니다. 실제로 모달 overlay 21곳과 `<button>` 171곳이 직접 마크업되어 있습니다.
- **루트 집중형의 한계:** 모든 정보를 루트 문서 하나에 넣으면 문서가 길어지고, 항상 로드되어 컨텍스트를 낭비합니다. 코드에서 멀리 떨어져 있어 코드와 어긋나기도 쉽습니다.

## 결정
1. **4계층 구조**
   - L1 프로젝트: 루트 `AGENTS.md`
   - L2 폴더: `src/{폴더}/AGENTS.md`
   - L3 화면: `src/app/(main)/**/AGENTS.md`
   - L4 기능: L3 문서 안의 `## 기능` 섹션. 문서가 150줄을 넘으면 그때 분리합니다.
2. **계층 지도의 원본은 루트 `AGENTS.md` §0입니다.** README는 AI 도구가 자동으로 읽지 않으므로 사람을 위한 요약과 링크만 둡니다.
3. **하위 폴더마다 `AGENTS.md` + `CLAUDE.md`(`@AGENTS.md`) 쌍을 둡니다.**
   - Codex와 Cursor는 하위 `AGENTS.md`를 자동으로 인식합니다.
   - Claude Code는 하위 `CLAUDE.md`를 해당 폴더 파일을 다룰 때 읽습니다.
4. **컴포넌트 카탈로그를 가장 중요한 컨텍스트로 둡니다.**
   - `src/components/AGENTS.md`: 계층 모델, 재사용 판단 순서, 전체 목록
   - `ui/AGENTS.md`: primitive 카드, 디자인 토큰, 표준 마크업
   - 도메인 폴더 `AGENTS.md`: props 시그니처와 사용 예가 담긴 컴포넌트 카드
   - L1에 "UI 작성 전 카탈로그 확인" 규칙을 두어 항상 로드되게 합니다.
5. **L3 화면 문서는 "조립도"(컴포넌트 트리) 중심으로 씁니다.** 새 화면은 비슷한 화면의 조립도를 참고합니다.
6. "레거시"를 **"실험 모듈"** 로 재정의합니다([modules.md](../modules.md)). 금지 규칙도 "레거시 import 금지"에서 "모듈 간 import 금지"로 바꿉니다.

## 결과
- 화면이나 컴포넌트를 바꿀 때는 해당 L3 문서와 카탈로그·카드도 갱신해야 합니다(L1 §7 체크리스트).
- 문서 파일 수가 늘어납니다(루트 포함 AGENTS.md 28개 + CLAUDE.md 28개). 대신 각 문서가 짧고 코드 옆에 있습니다.
- **후속 작업:** primitive(Modal, Button, Input, ConfirmDialog 등)를 추출하고 tailwind 토큰을 정의합니다([ui/AGENTS.md §4](../../src/components/ui/AGENTS.md)).
