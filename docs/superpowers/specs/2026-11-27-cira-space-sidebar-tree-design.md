# CIRA 사이드바: 팀(작업 공간)별 메뉴 트리 + 프로젝트 통합 메뉴

## 왜

지금은 프로젝트 아래 작업 공간(팀)을 드롭다운으로 하나 골라야 화면이 바뀐다. 팀마다 자기 보드·Task·설정이 사이드바에 바로 보이게 하고, 여러 팀을 합쳐 보는 것은 프로젝트 최상위 통합 메뉴에서 한다.

## 목표 / 비목표

- 목표: 사이드바에서 드롭다운을 없애고 팀마다 펼칠 수 있는 묶음(보드 · Task · 공간 설정)을 둔다. 최상위 통합 메뉴의 Task 는 모든 팀의 Task 를 한 목록으로 보여 준다.
- 비목표: 통합 보드(팀마다 워크플로가 달라 한 보드로 합칠 수 없음 — 사용자 결정 A). 백엔드 변경. URL 구조 변경.
- 반목표: 팀 화면을 열었는데 다른 팀 데이터가 섞이는 것. 기존 `?space=` 링크(알림·공유 링크)가 깨지는 것.

## 접근 (사용자가 1 선택)

1. **(선택)** `?space=` 쿼리를 유지하고 사이드바만 트리로. 변경: 사이드바, Task 목록, `withSpace`. 단점: 팀이 경로가 아니라 쿼리에 있음.
2. 경로에 팀(`/projects/{p}/spaces/{s}/…`). URL 은 분명하지만 보드·Task·공간 설정 폴더 이동과 링크 전부 수정 — 보이는 차이에 비해 변경이 몇 배.

## 설계

사이드바(프로젝트 안):
```
← 모든 프로젝트
CIRA
  Feature (전체 통합) · Task (전체) · 백로그 · 리포트 · 릴리스 · 위키 · 프로젝트 설정(ADMIN)
  ▾ HW팀            ← 지금 보고 있는 팀만 펼침, 나머지는 접힘(클릭하면 펼침)
      보드 · Task · 공간 설정(canManage)
  ▸ SW팀
  + 작업 공간 추가(ADMIN)
```
- 팀 메뉴 링크는 **기본 공간도 포함해 항상** `?space=<id>` 를 붙인다. 그래야 기본 팀의 Task 와 통합 Task 가 구분된다. `withSpace` 를 이렇게 바꾼다.
- 다른 화면(보드·설정)은 지금처럼 `?space=` 가 없으면 기본 공간 — 옛 링크 그대로 동작.
- Task 목록(`/issues`)만: `?space=` 가 없으면 **전체**(백엔드는 spaceId 없이 조회하면 이미 전체를 준다). 통합일 때 "공간" 열과 공간 필터를 보여 주고, 컬럼은 고정 필드만(팀마다 사용자 정의 필드가 달라서).
- 활성 표시: 팀 메뉴는 경로와 `?space=` 가 모두 맞을 때만. 통합 Task 는 `?space=` 가 없을 때만.
- 사이드바를 접었을 때(아이콘만): 팀은 이름 앞 두 글자 배지, 누르면 그 팀 보드로.
- 설정 화면 안의 사이드바(프로젝트 설정 / 작업 공간 설정 두 묶음)는 이번에 바꾸지 않는다.

## 빌더에게 맡김

- 통합 Task 목록에서 [Task 생성]: CreateIssueModal 이 이미 공간 선택을 갖고 있으니 그대로 쓴다(기본 = 기본 공간).
- 펼침 상태는 컴포넌트 상태로(저장소 직접 접근 금지 규칙), 지금 팀은 항상 펼침.
- mock `GET /v1/projects/:projectId/issues` 가 spaceId 없을 때 전체를 주는지 확인하고 맞춘다.
- 문서: cira shell 카드, issues L3, projects L3, hooks 표(`withSpace` 동작).
